# 施工人员工效智能感知后端开发进度

> 更新日期：2026-08-28  
> 对照文档：《施工人员工效智能感知功能及前后端接口规范-0825》  
> 当前阶段：可供前端联调，尚未达到正式生产部署条件

## 1. 总体进度

当前后端整体完成度约为 **80%**。

已经打通以下主要链路：

```text
场景图上传
→ 相机或历史视频登记
→ 标定点和工作区域配置
→ 创建分析任务
→ 人员姿态检测和跟踪
→ 俯视图投影及区域判断
→ 区域人数和工效累计
→ HTTP 查询或 WebSocket 实时推送
```

当前数据主要保存在进程内存中，服务重启后会丢失。MySQL、历史回放、正式鉴权和现场海康相机验证计划后续实施。

## 2. 已完成功能

### 2.1 场景与工效配置

- 上传 PNG/JPEG 场景俯视图；
- 校验图片格式、20 MB 大小限制和图像尺寸；
- 接收前端提交的相机点、场景点和工作区域；
- 校验至少 4 组标定特征点；
- 计算相机画面到归一化场景坐标的单应矩阵；
- 计算平均和最大重投影误差；
- 校验工作区域坐标、重复 ID、自交和零面积；
- 校验计划人数、要求时长及算法参数；
- 生成不可变的配置、标定和区域版本；
- 校验任务视频或相机与标定配置属于同一相机。

### 2.2 人员检测与跟踪

- 接入 Ultralytics YOLO Pose；
- 接入 ByteTrack，并持续保持视频内 `trackId`；
- 输出人员置信度、检测框和 COCO 17 个姿态关键点；
- 每个任务应用自身配置的 `personConfidence`；
- 优先使用双脚踝中点作为地面锚点；
- 脚踝置信度不足时退化为检测框底边中心；
- 支持 GPU/CPU、推理尺寸和跟踪器配置；
- 默认使用 `model/yolo11m-pose.pt`，也可通过环境变量覆盖。

### 2.3 视频与实时流

- 历史 MP4 上传和登记；
- 自动读取分辨率、FPS、总帧数和视频时长；
- 按视频时间戳处理历史视频，不按程序耗时累计工效；
- 支持 RTSP/RTMP 实时相机地址登记；
- 历史视频和实时流使用统一 `FrameSource` 分析流程；
- 实时流读取与算法推理解耦；
- 实时流只保留最新帧，避免延迟持续堆积；
- 支持首次连接超时、断流重连和协作停止。

### 2.4 区域判断与工效算法

- 将人员地面锚点投影到场景俯视图；
- 多边形边界包含的区域判断；
- `OUTSIDE/ENTERING/INSIDE/LEAVING/UNKNOWN` 状态机；
- 进入和离开持续时间防抖；
- 短时丢轨容忍；
- 人员处于 `INSIDE` 时标记为 `WORKING`；
- `INSIDE` 人员计入 `actualWorkingCount`；
- 人数达到 `expectedWorkerCount` 时累计班组合格工时；
- 计算 `headcountCompliant` 和 `efficiencyStatus`；
- 保存人数符合/不足时间区间；
- 修复 `qualifiedTeamWorkDurationSec` 在进入确认帧提前累计的问题；
- 限制过大帧间隔，避免断流导致工时虚增。

### 2.5 任务管理

- 创建实时相机或历史视频分析任务；
- 查询任务状态；
- 幂等停止任务；
- 后台线程执行分析；
- 支持以下任务状态：
  - `CREATED`
  - `STARTING`
  - `RUNNING`
  - `STOPPING`
  - `STOPPED`
  - `COMPLETED`
  - `FAILED`
- 支持任务取消、线程池关闭和排队任务清理；
- 记录模型执行异常和失败原因；
- 修复启动与停止同时发生时可能卡在 `STOPPING` 的竞争问题。

### 2.6 HTTP 接口

当前已实现：

| 方法 | 地址 | 用途 |
|---|---|---|
| GET | `/health` | 健康检查 |
| POST | `/api/work-efficiency/v1/scenes` | 上传场景俯视图 |
| GET | `/files/scenes/{sceneId}` | 获取场景图片 |
| POST | `/api/work-efficiency/v1/configurations` | 提交标定和工效配置 |
| POST | `/api/work-efficiency/v1/videos` | 上传并登记历史视频 |
| POST | `/api/work-efficiency/v1/cameras` | 登记 RTSP/RTMP 相机 |
| POST | `/api/work-efficiency/v1/tasks` | 创建分析任务 |
| GET | `/api/work-efficiency/v1/tasks/{taskId}` | 查询任务状态 |
| PATCH | `/api/work-efficiency/v1/tasks/{taskId}` | 停止任务 |
| GET | `/api/work-efficiency/v1/tasks/{taskId}/progress` | 查询处理进度 |
| GET | `/api/work-efficiency/v1/tasks/{taskId}/latest-result` | 查询最新帧结果 |
| GET | `/api/work-efficiency/v1/team-efficiency` | 查询区域工效汇总 |

`team-efficiency` 已支持：

- 使用 `taskId` 查询；
- 使用 `startTime/endTime` 查询；
- 使用 `areaId` 过滤；
- 返回符合时长、不足时长和 ISO 8601 时间区间。

### 2.7 WebSocket 实时推送

已实现规范地址：

```text
/ws/work-efficiency/v1/tasks/{taskId}
```

支持：

- `FRAME_RESULT` 实时分析消息；
- `ERROR` 错误消息；
- 帧序号、尺寸和 ISO 8601 `capturedAt`；
- 人员置信度、检测框、姿态关键点和地面锚点；
- 场景坐标、区域归属、工作状态和轨迹增量；
- 区域实际人数、计划人数、合格状态和累计工时；
- Bearer Header 或 `access_token`；
- 慢客户端只保留最新结果，不阻塞模型推理；
- 任务进入终态后结束推送；
- WebSocket 消息不包含历史视频处理进度。

### 2.8 响应与错误处理

- 统一 HTTP 响应字段：`requestId/success/code/message/data/timestamp`；
- 已覆盖主要错误码：
  - `WE0101` 参数错误；
  - `WE0102` 标定无效；
  - `WE0103` 区域无效；
  - `WE0104` 工效参数无效；
  - `WE0201` 输入不可用；
  - `WE0202` 配置未激活或不匹配；
  - `WE0301` 人员模型或分析工作器失败。

## 6. 当前限制

- 服务重启后内存中的场景、配置、任务和结果会丢失；
- 时间范围查询只能基于当前进程内已有数据；
- `poseSamplingMs` 已接收，但尚未用于数据库抽样保存；
- 尚未实现 `/api/work-efficiency/v1/playback`；
- 尚未完整实现 `WE0302` 空间映射失败和 `WE0401` 保存失败链路；
- 当前鉴权不包含用户、角色和权限体系；
- 海康相机的 RTSP 地址、认证、断流和长期运行尚未现场验证；
- 尚未进行完整 5 分钟视频的端到端标定与工效验收。
