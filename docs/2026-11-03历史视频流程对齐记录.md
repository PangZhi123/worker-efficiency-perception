## 修改原因

Java 调用 `POST /api/work-efficiency/v1/videos`，工效当前版本却只提供先创建 analysisId 的 historical-analyses 流程，造成对接协议不一致。原开发进度的旧接口表和后面的接口删除说明也互相矛盾。

本次以相邻 material-usage-perception 工程的实际视频上传、配置绑定和任务管理代码为基准，统一业务调用顺序。截图中的 HTTP 响应头缺失仍需部署日志确认；本次不将网络断连直接等同于路由不匹配。

## 第一轮修改（后续调整见文末）

- 新增 multipart `POST /videos`：file、cameraId、可选 capturedAt，返回 videoId 及元数据；默认 5 GiB，可配置上限；校验 MP4、首帧和空文件，失败清理；SHA256 去重与不同 cameraId 的独立登记。
- 增加 GET /videos 列表、单视频信息和代表帧预览，供工作台读取已登记素材。
- scenes 支持 videoId、description；历史配置通过 configurations 提交，检查视频、场景和 cameraId 一致性。
- tasks 支持 VIDEO_FILE，校验 videoId + configurationId，禁止传 cameraId、混用实时配置或跨视频配置。
- 新建任务原子占用资源；第二轮修正后，历史共用全局单名额，实时按相机互斥，两者互不占用。历史任务停止、失败、完成后均可新建 taskId 从头分析。
- 停止接口复用原任务管理器；返回 action；重复停止保持终态。新 VIDEO_FILE 对外将 CREATED/STARTING 表示为 QUEUED。
- 视频 capturedAt 随资源持久化，帧绝对时间据此计算；未修改工效算法、区域人数和计工规则。
- JSON 资源记录增加向后兼容的默认字段，保存视频元数据和场景绑定；归档仍包含配置、单应矩阵和场景图。
- 测试工作台历史页切换到 videoId/sceneId/configurationId 流程，上传或修改标定后清空配置选择，保存前禁用开始按钮。
- 保留旧 historical-analyses 接口及原有记录，原接口仍保持旧的 LOCKED 和完成后禁止重跑规则；新对接统一使用本次协议。

## 上线与边界

需部署当前 Python 代码并重启服务；Java 保留 /videos 上传地址，通过 videoId + 所选 configurationId 创建 VIDEO_FILE 任务，并提供有效且带时区的录像开始时间。已有配置可直接复用，新建配置时再进行场景上传和标定。

公开任务状态和主要成功 HTTP 状态已按新历史流程对齐。前缀、WE 错误码、工效配置和结果、persistPoseAndTrajectory 选项保持工效语义。实时和旧接口兼容性优先，不宣称两个服务所有字段逐字相同。

## 第二轮任务冲突修正

针对物料当日刚修正的 MP0203 问题，工效原先也存在实时任务阻止同相机历史分析的情况。本轮改为历史全局单名额、实时按相机互斥，实时与历史可并行，沿用 WE0203 和 HTTP 409 报告真正的调度冲突。

旧 historical-analyses 路由也通过仓储内相同的原子检查进入历史名额，不能和新 VIDEO_FILE 路由各启动一份历史任务。CREATED、STARTING、RUNNING、STOPPING 都占用名额，终态释放；停止仍为异步，不提前释放名额，也未强行终止卡住的推理或取流。

第二轮当时只调整调度、冲突提示、页面说明及文档；配置复用、recordingStartedAt 和任务快照在后续第三轮完成。

新增测试覆盖实时与历史同相机共存、不同相机历史任务冲突、各非终态继续占用、停止后重启，以及新旧历史路由共用名额。完整回归 75 项通过；定向 Ruff、JavaScript 语法和 diff 检查通过。1103 Word 同步更新调度规则并重新检查排版。本轮未再次执行完整浏览器交互，页面仅增加调度提示。

## 第三轮配置复用与录像时间对齐

用户确认同步方向为“工效按物料改”。本轮按物料最新实现，取消 VIDEO_FILE 任务创建时的配置 videoId 和来源 cameraId 匹配要求，允许选择已有相机、其他视频或当前视频配置。新建专属场景/配置时的绑定校验保留；实时任务仍验证相机一致且禁止视频配置。

任务请求新增 recordingStartedAt，显式时间必须有效且带时区；未传时采用视频 capturedAt，后者无有效时区则返回 422。新协议不再用任务创建时间代替缺失的录像开始时间。帧、WebSocket、归档和工效区间按录像开始时间计算；时间范围查询用录像开始时间筛选新历史任务。

新实时、历史及兼容历史任务保存深拷贝配置快照，执行再次复制，任务配置归档优先使用快照。旧资源文件新增字段有默认值，仍可读取；旧 historical-analyses 接口支持可选录像时间，但不破坏旧调用的缺省行为。

工作台增加读取已有配置、使用实时页配置和带时区的录像时间输入。未提供有效时间时禁止启动，新建标定配置的入口继续保留。接口规范、README、1103 Word 和开发进度同步更新。

新增自动化覆盖缺省/无时区/非法录像时间、显式时间优先级、跨相机已有配置复用、无 cameraId 的旧版历史配置复用、配置快照在原配置修改/删除后的执行和归档、重启恢复及录像日期查询。完整回归 87 项通过；定向 Ruff、Node 语法和 diff 检查通过。浏览器分别验证新建配置流程和复用实时配置流程，包括时间校验、启动、快照响应和停止，无页面 JavaScript 异常。
