## 二、WebSocket 任务结束通知

- 在最后一帧结果后发送 `TASK_STATUS`，包含 `taskId/taskStatus/endedAt/error`。
- 支持 `COMPLETED`、`STOPPED`、`FAILED`；失败时保留原有 `ERROR` 消息以兼容旧客户端。
- 终态消息发送后，以关闭码 1000 正常关闭连接。
- 重连已结束任务也发送终态，包括无帧结果的任务。
- 检测到终态后重新读取最新快照，避免结束竞争导致最后一帧漏发。
- 本地测试工作台继续使用 HTTP 轮询，查询到终态后停止轮询并显示状态提示。

独立业务前端需处理 `TASK_STATUS`，不能仅凭 WebSocket 断线认定任务成功。协议及接口细节见 [资源管理与任务结束通知](2026-11-04资源管理与任务结束通知.md)。

## 三、相机、配置恢复与删除

新增接口，统一前缀 `/api/work-efficiency/v1`，沿用 Bearer 鉴权：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/cameras` | 获取相机列表，不返回流地址 |
| DELETE | `/cameras/{cameraId}` | 删除相机登记 |
| GET | `/configurations` | 获取未删除的配置列表 |
| DELETE | `/configurations/{configurationId}` | 逻辑删除配置 |

- 默认 JSON 仓储原本已保存相机、配置；本次将新增删除操作纳入持久化，删除后重启不会恢复。
- 配置标记为 `DELETED`，从列表隐藏、详情返回 404，禁止用于新任务；保留原记录和已有任务配置快照。
- 删除相机不级联删除配置、视频及历史结果；同一 ID 可重新登记。
- 相机存在非终态实时任务时返回 409 / WE0203，须先停止任务再删除，避免影响任务启动取流。
- 页面启动或检查连接时从服务端恢复列表，登记、保存、删除后刷新列表。
- 相机页新增选择与删除入口；实时分析页新增配置选择、读取、删除入口；历史配置输入框提供已保存 ID 候选。

主要修改文件为 `api/app.py`、`api/repository.py`、`persistence.py`、`web/index.html`、`web/app.js` 和 `tests/work_efficiency/test_api.py`。
