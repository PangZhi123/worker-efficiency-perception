# 2026-11-04 资源管理与任务结束通知

## WebSocket 任务结束

`/ws/work-efficiency/v1/tasks/{taskId}` 在最后一帧结果之后发送：

```json
{
  "type": "TASK_STATUS",
  "taskId": "task_xxx",
  "taskStatus": "COMPLETED",
  "endedAt": "2026-11-04T01:00:00+00:00",
  "error": null
}
```

`taskStatus` 支持 `COMPLETED`、`STOPPED`、`FAILED`。失败时 `error` 包含 `code`、`message`，同时保留原有 `ERROR` 消息以兼容旧客户端。随后服务端以 1000 关闭连接。重连已结束任务也会发送终态，包括没有帧结果的任务。

业务前端应处理 `TASK_STATUS`，显示结束或失败提示并停止刷新；不能仅凭断线认定成功。本地测试工作台继续使用 HTTP 轮询，在查询到终态时显示提示。

## 相机及配置列表、删除

统一前缀 `/api/work-efficiency/v1`，沿用现有 Bearer 鉴权：

| 方法 | 路径 | 行为 |
| --- | --- | --- |
| GET | `/cameras` | 返回 `data.items`，包含 `cameraId/status`，不返回流地址 |
| DELETE | `/cameras/{cameraId}` | 删除相机登记；仍有非终态实时任务时返回 409 / WE0203，须先停止任务 |
| GET | `/configurations` | 返回未删除配置的 ID、类型、相机、场景及 analysisId |
| DELETE | `/configurations/{configurationId}` | 持久化标记 DELETED，列表隐藏、详情返回 404，禁止用于新任务 |

删除接口幂等。删除相机不级联删除配置、素材和历史结果；删除配置保留原始记录，已有任务使用创建时的配置快照。相机可用同一 ID 重新登记。

测试页面启动或检查连接时从服务端加载列表；登记相机、保存配置及删除后刷新列表。相机管理提供选择、删除入口；实时分析页提供配置选择、读取与删除入口；历史配置输入框提供已保存 ID 候选。

默认 `main:app` 使用 JSON 仓储，新增删除操作也会保存并在重启后恢复。结果目录默认为 `data/results`，可通过 `WORK_EFFICIENCY_RESULTS_DIRECTORY` 指定固定位置；重新部署必须保留该目录。直接调用 `create_app()` 默认仍为内存仓储。

## 验证范围

自动化覆盖终态通知、无帧任务、终态重连、正常关闭、最后一帧顺序、相机与配置重启恢复及删除、删除后新任务拒绝、已有任务快照不变、活动相机删除冲突和管理接口鉴权。

尚未进行独立业务前端适配、真实相机验证或远端部署。
